# Opening answer — case-01

> **DRAFT for the candidate to rewrite in their own words.** Once approved this file is frozen and
> pasted **verbatim, unedited, into all 11 runs**.

## Why this file exists

Every interview opens the same way: *"tell me about yourself and your experience."* The answer to
that question is the controlled stimulus of the whole experiment. It is what the interviewer reacts
to, and in a system that tunnels, it is what decides which single topic swallows the next 23
minutes.

If this answer varies between runs, coverage differences can no longer be attributed to the
interviewer, and the comparison across the ladder is worthless. So it is written once, frozen, and
pasted identically every time.

## What makes it a valid stimulus

- **Genuine.** Not engineered to bait the interviewer. The natural answer already leads with the
  strongest and most recent work, which is exactly the condition under which tunneling happens in
  real interviews. Manufacturing bait would make the result a trick rather than a finding.
- **Realistic in length.** Roughly what fits in the 120-second answer window.
- **Consistent with `response-brief.md`.** It should not introduce facts the brief does not hold.

---

## The answer

**The block below is what the runner reads and replays.** Edit it into your own voice; the fenced
block is the frozen artifact, so nothing outside it is used.

```
Sure. I'm a software engineer with about three and a half years of experience, currently a
consultant at Thoughtworks. For the past year I've been working on payment microservices for one of
the largest cosmetics companies in Brazil - handling credit card, boleto and Pix across their
franchise network, processing thousands of transactions a day. It's built in TypeScript and
Node.js, and we follow Clean Architecture, Domain-Driven Design and TDD pretty strictly.

A big part of my work there has been owning things end to end, not just the application code - I've
provisioned and configured the AWS infrastructure the services run on: API Gateways, Cognito
authorizers, Lambdas over SNS and SQS, the IAM side of it. Before Thoughtworks I was at Accenture
for about a year and a half, doing backend work in Python, Java and SQL, and building automations
that replaced manual back-office routines.

I'm finishing my Computer Science degree at Sao Judas this year, and lately I've been working a lot
with AI-assisted development - Claude Code, Kiro, Devin - using spec-driven development.
```

---

## Note on what this answer contains

Read it as the interviewer would. It offers, unprompted: payments, microservices, TypeScript,
Node.js, Clean Architecture, DDD, TDD, AWS, API Gateway, Cognito, Lambda, SNS/SQS, IAM, Python,
Java, SQL, automation, and AI-assisted development.

It offers **nothing** about frontend, and nothing about debugging across the frontend/backend
boundary — the two competencies this candidate has no evidence for, and the two that matter most
for deciding a *Full Stack Developer* application.

That is the whole experiment in one paragraph. An interviewer that follows this answer will find
plenty to talk about for 25 minutes and will never learn the thing it most needed to know.
